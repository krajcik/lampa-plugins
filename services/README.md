# Домашний источник IMDb

`imdb-ratings.py` использует официальный
[title.ratings.tsv.gz](https://data.imdb.com/non-commercial-datasets/).
IMDb обновляет набор ежедневно; разрешены локальные копии для личного
некоммерческого использования в рамках условий IMDb. Сам набор в Git не входит.
API-ключей, аккаунтов и сторонних Python-библиотек нет.

## Локальный запуск

Из корня репозитория:

```sh
python3 services/imdb-ratings.py update
python3 services/imdb-ratings.py
curl http://127.0.0.1:9120/rating/tt0816692
```

Переменные окружения: `IMDB_RATINGS_DB` (по умолчанию `.local/imdb-ratings.sqlite`),
`IMDB_RATINGS_HOST` (`127.0.0.1`) и `IMDB_RATINGS_PORT` (`9120`).
Ответ содержит `id`, `rating` и `votes`; отсутствие оценки — `rating: null`.
`/health` показывает готовность и время обновления базы. Изменяющих HTTP-методов нет.
Некорректный путь даёт 404, недоступная база — 503. CORS разрешает чтение из Lampa.

Обновление потоково читает gzip/TSV, проверяет поля и строит новую SQLite рядом
со старой. Только успешно построенная непустая база заменяет старую атомарно.
Ошибка сети, формата или строки оставляет предыдущую базу доступной.

На локальной проверке 24.10.2026: 1 724 693 оценки, SQLite 80.4 MiB,
процесс API около 13 MiB RSS на Mac. Это наблюдение, не замер ресурсов VM.

## Домашняя установка

Сервис развёрнут рядом с Jackett в VM110:

- `/opt/imdb-ratings/imdb-ratings.py`, отдельный пользователь `imdb-ratings`;
- `/var/lib/imdb-ratings/ratings.sqlite` для данных;
- systemd-файлы из `systemd/`: API на 9120 и ежедневное обновление;
- private HTTPS VM102 → VM110:9120, имя `imdb.home.lurno.ru`;
- только GET `/rating/tt…`, GET `/health` и OPTIONS; публичный ingress не меняется.

Добавлены точная домашняя DNS-запись, два firewall-правила VM102/110 на 9120
и отдельный private-блок Caddy. Сертификат доверенный; публичного API-маршрута нет.
Шаблон API слушает все интерфейсы VM: его нужно применять только вместе с
private network/firewall. На VM обновление заняло около 14 секунд, пик памяти
98.8 MiB; процесс API после запуска использовал около 11 MiB в cgroup.
Лимиты памяти — 96 MiB для API, 256 MiB для ежедневного обновления.

В плагине это резерв для IMDb. Готовые оценки IMDb/КП и недостающий КП
получаются из карточки и метаданных CUB. Сервис не собирает оценки Кинопоиска.
